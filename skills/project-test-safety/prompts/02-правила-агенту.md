# 2 · Правило для агента в файле проекта

```
Сначала прочитай `тесты/контекст.md` — там результат диагностики: стек, команды,
база, главные действия и что нельзя ломать. Если файла нет — скажи мне об этом
и разберись сам, но короче.

ЧТО НАПИСАТЬ

Раздел «Как проверять работу». Правило: задача не закрыта, пока команда проверки
не завершилась успешно И ты не показал её вывод в ответе.

Команду называй ровно так, как она вызывается в этом проекте — точную строку
возьми из контекста.

Запреты, перечисли явно:
- не отвечать «работает» без вывода команды;
- не править тест и рабочий код в одном заходе;
- не ослаблять проверки в тесте, когда чинишь приложение;
- не запускать проверки в режиме слежения.

До 20 строк, без воды.

КУДА НАПИСАТЬ

Основной файл — `AGENTS.md` в корне проекта. Это общий формат, его читает
большинство агентов. Нет файла — создай, есть — допиши в конец, существующее
не трогай.

Дальше мостик. Часть агентов `AGENTS.md` не читает вообще, у них свой файл.
Ответь себе честно: ТЫ САМ из какого файла в этом проекте читаешь постоянные
инструкции?

- читаешь `AGENTS.md` — всё, больше ничего не нужно;
- читаешь свой файл — создай его и поставь в нём ссылку на общий: строкой
  `@AGENTS.md` или фразой «правила проекта смотри в AGENTS.md». Полную копию
  правила туда не переноси, чтобы не расходились.

Если не уверен, откуда читаешь инструкции, — так и скажи, не угадывай. Я подскажу.

ПРОВЕРЬ, ЧТО ЭТО РАБОТАЕТ

Скажи прямо: из какого файла ты будешь читать это правило в следующих сессиях,
и подтверди, что сейчас его видишь.

Потом обнови раздел «Команды» в `тесты/контекст.md` — допиши, где лежит правило.
```

**Что должно получиться.** `AGENTS.md` с коротким разделом — и, если ваш агент читает
не его, ещё маленький файл-мостик со ссылкой. Плюс прямой ответ, откуда агент это читает.

**Обязательно проверьте сами.** Слова агента про собственную конфигурацию — не
доказательство. Дайте любую мелкую задачу: «поправь текст на кнопке». Если в ответе
пришёл вывод команды проверки, а не слово «готово» — правило работает. Если пришло
«готово» — скажите: «правило не сработало, разберись почему».

## Нет, `AGENTS.md` читают не все

Формат общий и самый широкий из существующих — им пользуются десятки инструментов,
и он живёт под Linux Foundation. Но универсальным его называть рано.

| Агент | Читает `AGENTS.md` | Что делать |
|---|---|---|
| Codex | да, основной файл | ничего |
| Cursor | да | ничего |
| opencode | да | ничего |
| Zed, Warp, Amp, Factory | да | ничего |
| GitHub Copilot | да, но не во всех режимах | плюс `.github/copilot-instructions.md` |
| Antigravity | да (по документации Google) | проверьте на мелкой задаче |
| **Claude Code** | **нет** | нужен мостик, см. ниже |
| Gemini CLI | нет по умолчанию, но включается | в `.gemini/settings.json`: `"context": { "fileName": "AGENTS.md" }` |
| Aider | нет | `read: AGENTS.md` в `.aider.conf.yml` |

Данные на конец августа 2026 — это всё быстро меняется, так что проверка на мелкой
задаче важнее любой таблицы.

### Claude Code — самый частый случай

Anthropic пишет прямым текстом: Claude Code читает `CLAUDE.md`, а не `AGENTS.md`.
Если вы работаете в нём и положите правило только в `AGENTS.md` — оно просто
не загрузится, молча.

Мостик в две строки. Создайте `CLAUDE.md` в корне:

```markdown
@AGENTS.md
```

Всё, дальше правило подтягивается из общего файла. Ниже в этом же файле можно
дописать что-то специфичное для Claude Code, если понадобится.

Кто дружит с командной строкой — вместо этого подойдёт ссылка на файл:

```
ln -s AGENTS.md CLAUDE.md
```

На Windows для такой ссылки нужны права администратора, так что там проще `@AGENTS.md`.

### Если вашего агента в таблице нет

Спросите у самого агента и **проверьте на мелкой задаче** — или поищите в его
документации слова «rules» или «instructions». Списки в интернете устаревают
быстрее, чем обновляются.
