# Project Test Safety — 9-промптный пайплайн (AlexeyTripleA pack)

Промпты лежат в `prompts/` (оригиналы, на русском, самодостаточные — вставляются в задачу субагенту как есть).

## Когда применять
- В проекте нет тестов / линтера / команды проверки, или непонятно, что реально запускается.
- Пользователь просит «защиту от поломок», safety net, тестовую обвязку с нуля.

## Пайплайн (адаптация под наш флот)

1. **Диагностика** (`prompts/00-диагностика.md`) → спавни **@scout** (read-only). Результат: `тесты/контекст.md` + `тесты/риски.md` в проекте. НЕ удалять, все следующие шаги их читают.
2. По маршруту из диагностики, только названные шаги:
   - `01-одна-команда.md` — свести проверки в одну команду → **@fixer**
   - `02-правила-агенту.md` — раздел «Как проверять работу» в AGENTS.md проекта (у нас уже покрыто HONESTY-законом — применять только если проектный AGENTS.md пуст)
   - `03-предохранитель-базы.md` — тесты никогда не трогают боевую БД → **@fixer**
   - `04-тесты-логики.md` — 3–5 тестов на вычисления → **@fixer** (TDD-профиль)
   - `05-ответы-приложения.md` — права/доступ/состав выдачи → **@fixer**
   - `06-браузерный-тест.md` + `07-браузер-агенту.md` → **@designer** (у него browser) или @fixer с browser-доступом
   - `08-проверки-на-сервере.md` — CI-прогон → по `rule://enterprise-directives`
3. Дополнительные пакеты по домену — `prompts/дополнительно/` (оплаты, телеграм-бот, фоновые задачи, внешние сервисы, тесты-с-базой, скриншот-тесты, ответы-нейронки).

## Правила
- Шаг 00 — всегда первый и только read-only (+2 файла отчёта).
- Субагентам передавать файл промпта целиком через `local://` или абсолютный путь, НЕ пересказывать.
- Каждый шаг закрывается выводом команды проверки (HONESTY): нет вывода — шаг не выполнен.
