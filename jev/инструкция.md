# Jev в Claude Code — инструкция

Плагин к ролику «Claude Code + Jev: 12 концептов, которые экономят токены». Версия 1.1.

Jev — модель, которая не пишет текст, а только выбирает: да или нет, какой вариант, какая ступень.
Плагин отдаёт ей мелкие решения, а думать и писать оставляет Claude Code. Что он умеет:

- **Роутер моделей.** Перед каждой задачей Jev решает, какой модели она по силам. Простую задачу
  делает дешёвая модель, сложную — сильная.
- **Выбор скилла.** Jev подсказывает Claude Code, какой из твоих скиллов открыть под задачу.
- **Решения по твоим данным.** Таблица, выгрузка, папка файлов — Jev разбирает каждую запись
  по твоему вопросу: ответить или нет, спам или идея, срочно или подождёт.
- **Проверка на своих данных.** Сравнивает ответы Jev с тем, как разобрал человек, — прежде чем
  доверять ему работу.

---

## Что понадобится

- **Claude Code** — в терминале, во вкладке Code приложения Claude Desktop, в VS Code или JetBrains.
  В обычном чате Claude плагин не работает: там нет хуков.
- **Python 3.8 или новее.** На Mac он уже есть, ставить ничего не нужно.
- **Ключ Jev** — любой из двух:
  - OpenRouter — [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys), без листа ожидания;
  - TypeSafe — [console.typesafe.ai/keys](https://console.typesafe.ai/keys).

## Шаг 1. Поставить плагин

Распакуй архив `jev-1.1.0.zip` — получится папка `jev`. Открой любой проект в Claude Code и напиши:

> Установи плагин Jev из папки <путь к папке jev>: выполни `claude plugin marketplace add <путь>`
> и `claude plugin install jev@nick-vels`

Или сам в терминале — те же две команды:

```bash
claude plugin marketplace add ~/Downloads/jev
```

```bash
claude plugin install jev@nick-vels
```

Перезапусти Claude Code. Плагин ставится один раз и доступен во всех проектах.

**Обновляешься с версии 1.0?** Распакуй новый архив и напиши в Claude Code:

> Обнови плагин Jev из папки <путь к новой папке jev>: выполни `claude plugin marketplace remove nick-vels`,
> `claude plugin marketplace add <путь>` и `claude plugin install jev@nick-vels`; если скажет, что
> плагин уже установлен, — `claude plugin update jev@nick-vels`

Потом перезапусти Claude Code. Признак новой версии — команд `/jev:haiku`, `/jev:sonnet`, `/jev:opus`
в списке больше нет.

## Шаг 2. Вставить ключ

Напиши в Claude Code:

```
/jev:setup
```

Плагин создаст файл `~/.claude/jev.env` и откроет его в редакторе. Вставь ключ сразу после
`JEV_API_KEY=`, сохрани и снова напиши `/jev:setup`. Должна появиться строка
**«Связь с Jev: ок»**.

- Ключ в чат не присылай — плагин найдёт его сам.
- Файл лежит вне папки плагина: ключ переживёт обновление и работает во всех проектах.
- Нужен отдельный ключ для одного проекта — та же строка `JEV_API_KEY=…` в файле `.env` в корне
  проекта. Проверь, что `.env` есть в `.gitignore`.

---

## Шаг 3. Включить роутер моделей

Роутер включается **в каждом проекте отдельно**. Открой проект и напиши:

```
/jev:on
```

Со следующего сообщения перед каждой задачей Jev за полсекунды оценивает две вещи: насколько она
сложная и опирается ли она на ваш разговор («продолжай», «ещё один такой же», «исправь, что
сделал»). Дальше Claude Code поступает так:

| Задача | Что делает Claude Code |
|---|---|
| по силам модели, на которой ты работаешь | делает сам, как обычно |
| простая → Haiku, средняя → Sonnet | сам отдаёт её **субагенту** на этой модели и передаёт ему нужное из разговора |
| сложная → Opus, предельная → Fable, а твоя модель слабее | не начинает работу. Задача держится на разговоре — советует переключить модель. Не держится — даёт выбор: переключить модель или отдать задачу субагенту |
| сложная или предельная, а твоя модель сильнее нужной | делает сам и в конце предлагает переключиться на модель попроще — дешевле |

**Переключить модель** — список моделей внизу окна, в терминале — команда `/model`. После этого
напиши «продолжай»: весь разговор на месте.

Одно и то же предложение роутер в одном диалоге повторяет только один раз. Сказал «делай на этой
модели» — больше не спросит.

Выключить роутер: `/jev:off`. Включить только роутер — `/jev:on router`, только подсказку скилла —
`/jev:on skills`.

### Как проверить, что роутер работает

Поработай немного и напиши `/jev:setup`. Смотри на две строки:

```
Решения роутера: отдал субагентам — sonnet 2, haiku 1 · предложил переключить модель — на fable 1
Кто отвечал в сессии …:
  основной диалог: claude-opus-5-5 — 12
  субагенты: claude-sonnet-5 — 4, claude-haiku-4-5 — 2
```

Если в строке «субагенты» есть Haiku или Sonnet — роутер экономит. Модель внизу окна при этом
не меняется: там показана модель твоего диалога, а не субагентов.

## Шаг 4. Решения по твоим данным — `/jev:run`

Пишешь словами, что решить по каждой записи и где лежат данные:

> /jev:run разбери комментарии из comments.csv: на какие ответить, где идея для ролика, где спам

> /jev:run по папке заявки/ — какие заявки горячие, а какие можно отложить

Одна команда — сразу результат. Плагин сам составит вопросы к Jev, прогонит весь файл и сохранит
ответы в таблицу `<имя файла>.jev.csv`. Записи, где Jev не уверен, перечитывает Claude Code.
Переспросит, только если не назван файл.

Повторить ту же задачу на новых данных:

> /jev:run comments новые-комментарии.csv

Подходят CSV, JSONL, JSON-массив или папка файлов (одна запись — один файл).

---

## Шаг 5. Проверить Jev на своих данных — `/jev:check`

Прежде чем доверять Jev работу, сравни его с человеком. Нужен файл на 30–100 записей, которые ты
уже разобрал сам: правильные ответы — в колонках `ответ_<вопрос>`. Нет такого файла — Claude Code
поможет собрать.

> /jev:check comments размеченные.csv — и сравни с Sonnet

Получишь отчёт: в скольких записях Jev совпал с тобой, в скольких — Sonnet, и список расхождений.
Чаще всего расхождение значит, что вопрос размыт: Claude Code допишет критерий, и сверку можно
прогнать ещё раз.

## Все команды

| Команда | Что делает |
|---|---|
| `/jev:setup` | ключ, связь с Jev, что включено, сколько потрачено, какие модели отвечали |
| `/jev:on` · `/jev:off` | включить и выключить роутер и подсказку скилла в этом проекте |
| `/jev:run` | решение по каждой записи файла или папки |
| `/jev:check` | сверка Jev с разметкой человека и с Sonnet |

Свои пороги и задачи лежат в одном файле проекта — `.claude/jev/questions.json`. Менять их можно
словами: «сделай роутер осторожнее», «в задаче comments добавь вариант „жалоба“».

## Если что-то не так

| Что видишь | Что сделать |
|---|---|
| «Связь с Jev: ошибка — HTTP 401» | ключ неверный или отозван: создай новый и вставь в `~/.claude/jev.env` |
| «Связь с Jev: ошибка — timed out» | Jev не открывается напрямую — проверь прокси. Если открывается без прокси, добавь `openrouter.ai` и `api.typesafe.ai` в `NO_PROXY` |
| роутер молчит | он включён в другом проекте — напиши `/jev:on` здесь. Ещё роутер пропускает сообщения короче 25 символов и команды со слэша |
| модель внизу окна не меняется | так и должно быть: субагенты работают на своей модели, а внизу — модель диалога. Кто отвечал на самом деле — в `/jev:setup` |

## Что изменилось с ролика (версия 1.1)

В ролике роутер менял модель «прямо в этом диалоге, до конца ответа» — скиллом с полем `model`.
Сейчас Claude Code это поле не применяет, если скилл вызвал сам Claude: ответ всё равно пишет
модель диалога. Это ошибка Claude Code:
[#79664](https://github.com/anthropics/claude-code/issues/79664),
[#85658](https://github.com/anthropics/claude-code/issues/85658).

Поэтому в версии 1.1:

- простые и средние задачи уходят **субагенту** — у него модель меняется на деле, это видно в `/jev:setup`;
- для сложных задач (Opus, Fable) решаешь ты: переключить модель в диалоге или отдать субагенту;
- добавлена модель **Fable** — для предельных задач;
- команды `/jev:haiku`, `/jev:sonnet`, `/jev:opus` убраны: модель вручную меняется списком моделей.

## Честно о границах

- **Роутер советует, а не командует.** Отдать задачу субагенту решает Claude Code, и сам этот шаг
  делает модель диалога: читает разговор и ставит задачу.
- **Субагент окупается на объёмной работе.** Поиск, чтение многих файлов, правки — выгодно: всё
  это идёт через дешёвую модель, а основной достаётся короткий итог. Если результат — текст в чат,
  основная модель выводит его ещё раз, и экономии почти нет. На ответ в одну строку субагента
  не зовут.
- **Субагент не видит разговор.** Claude Code передаёт ему запрос и нужное из диалога сам.
  Поэтому задачи, которые держатся на всём разговоре, роутер субагенту не отдаёт.
- **Русский — не основной язык Jev.** Документация TypeSafe прямо говорит: на других языках он
  работает хуже, чем на английском. Поэтому `/jev:check` на своих данных — не формальность.
- **Выбор скилла экономит на промахах, а не на описаниях.** В кукбуке TypeSafe Haiku открывал
  не тот скилл в 16,8% случаев, с подсказкой Jev — в 7,3%. Плагин видит скиллы из `.claude/skills`
  проекта и `~/.claude/skills`. Скиллы других плагинов и скиллы, которые Claude не вызывает сам
  (`disable-model-invocation: true`), в выбор не попадают.
- **При включённом роутере каждый твой запрос уходит в Jev** — к TypeSafe или OpenRouter. Запросы,
  похожие на ключи и пароли, плагин не отправляет. В проектах с закрытыми данными — `/jev:off`.
- **Цена Jev:** $0,042 за миллион входных токенов, выход бесплатный. Сколько потратил — `/jev:setup`.
- **Через прокси медленнее.** Наш замер на 155 записях через OpenRouter: 7 с напрямую, 25 с через
  прокси.
