# Слепой аудит воркфлоу: слепые пятна, слабые места, излишества

## 1. Агностичность (модель, провайдер, ОС, пути)
- **Факт**: Воркфлоу жестко привязан к Gemini / Nullform Gateway, Windows-путям и PowerShell.
- **Доказательства**:
  - Фоллбэк модели: `node tools/oracle-model.mjs list --models /dev/null --json` -> `{"resolved":"gemini-3.8-flash-high","isFallback":true}` (`FALLBACK_MODEL` зашит в коде `tools/oracle-model.mjs:19`).
  - Скиллы дизайна: `grep -n "GEMINI_API_KEY" skills/design/scripts/cip/generate.py` -> строка 212 (жесткая зависимость от Google Gemini API и библиотеки `google-genai`).
  - Абсолютные пути Windows: `grep -n "D:/ohmypi" agent/agents/fixer.md` -> строка 70 (`node "D:/ohmypi/tools/test-lens.mjs"`); `tools/benchmark.mjs:426` (`"D:/Python312/python.exe"`).
  - Платформа: `git ls-files "*.ps1"` -> 7 файлов, `git ls-files "*.sh"` -> 0 файлов в корне/tools (нет bash-скриптов установки и валидации).
- **Риск**: При смене провайдера на Ollama/Claude `oracle-model.mjs ensure` форсирует недоступную модель. На Linux/macOS падают Fixer (не находит `D:/ohmypi`) и установщик (`install.ps1` требует PowerShell Core, команда `powershell` отсутствует).
- **Рекомендация**: Заменить `FALLBACK_MODEL` на первую доступную модель из `models.yml`; заменить `D:/ohmypi` в `fixer.md` на `<HARNESS>` (с подстановкой в инсталлере); добавить bash-скрипты `install.sh` и `verify.sh`.

## 2. Минимализм и излишества (код, манифест, дубли)
- **Факт**: Раздутый объем `tools/`, несинхронизированные скиллы и массовое дублирование утилит.
- **Доказательства**:
  - Объем: 26 файлов, 14 295 строк кода в `tools/` (топ: `benchmark.mjs` 1608, `dashboard.mjs` 1542, `doctor.mjs` 1308).
  - Манифест: В `tools/sync.ps1` указан 1 скилл (`architecture-observability`, который удален из репо). Остальные 69 скиллов в репозитории не отслеживаются синк-манифестом.
  - Дублирование: `parseArgs` независимо реализован в 15 инструментах; парсинг `.jsonl` сессий независимо реализован в 4 инструментах (`session_cost.py`, `cache-doctor.mjs`, `usage-audit.mjs`, `dashboard.mjs`).
  - Мертвый код: 30+ неиспользуемых экспортов (`TASK_TIERS`, `collectDebt`, `runChecks`, `portForSession`, `sessionKey` и др.).
- **Риск**: Дрейф 69 скиллов между репозиторием и харнессом; скрытые баги из-за расхождения логики парсинга аргументов и сессий.
- **Рекомендация**: Создать общий модуль `tools/lib/cli.mjs` и `tools/lib/session.mjs`; удалить мертвые экспорты; включить скиллы в манифест синхронизации.

## 3. Изоляция сессий (гонки и конкурентность)
- **Факт**: Отсутствие сессионной изоляции для стейта, метрик и дашборда при одновременной работе агентов в одном проекте.
- **Доказательства**:
  - `.workflow/state.json`: `tools/workflow.mjs:118-123` использует статический `state.json.tmp`. Две параллельные сессии перезаписывают один файл; на Windows возникает коллизия `renameSync`.
  - `.workflow/metrics.jsonl` и `events.jsonl`: `appendFileSync` без файловых блокировок (lockfile/flock) ведет к повреждению строк при параллельной записи.
  - Порт и рантайм: `tools/workflow.mjs:336` вызывает `dashboard.mjs --ensure --root <root>` без сессионного ключа. Обе сессии делят порт 4200 и `.workflow/dashboard.json`, перетирая URL и контекст.
- **Риск**: Вторая сессия стирает тир, стадию и открытые гейты первой сессии; дашборд показывает случайное состояние одной из сессий.
- **Рекомендация**: Изолировать стейт по session-id (`.workflow/sessions/<id>/state.json`); использовать уникальные временные файлы (`state.<uuid>.tmp`); активировать изоляцию портов (`portForSession`) в `workflow.mjs`.

## 4. Скорость и стоимость (промпты и контекст)
- **Факт**: В каждую сессию загружается избыточный системный контекст.
- **Доказательства**:
  - `node tools/prompt-lint.mjs sizes --root . --json`: 86 957 байт (~87 КБ, ~22 000 токенов) суммарно. На старте каждой сессии безусловно инжектируются: `AGENTS.md` (11 062 Б) + 68 скиллов (22 425 Б) + правила (6 863 Б) = более 40 КБ.
  - 90-дневный аудит (`tools/usage-audit.mjs`): 37 из 68 скиллов ни разу не использовались; 17 скиллов требуются только роли `@designer`, 4 — только для Paseo.
- **Риск**: Лишние расходы токенов на каждом шаге агента; деградация внимания моделей из-за длинного системного промпта; медленный TTFT.
- **Рекомендация**: Внедрить lazy-загрузку скиллов по требованию; исключить 37 неиспользуемых скиллов из системного промпта; передавать дизайнеру специализированную палитру скиллов.

## 5. Поддерживаемость (сложность, дублирование, тесты)
- **Факт**: Пробелы в тестовом покрытии ключевых инструментов и хрупкий самописный парсинг YAML.
- **Доказательства**:
  - Тесты: `codemap.mjs` (213 строк), `glossary.mjs` (295 строк), `replay.mjs` (353 строк) — суммарно 861 строка кода без единого юнит-теста в `tools/tests/`.
  - Хрупкий YAML: `tools/oracle-model.mjs:77` и `tools/memory-cadence.mjs:18` используют самописные регулярные выражения для чтения YAML, которые падают на многострочных значениях, вложенных объектах и кавычках.
- **Риск**: Незамеченные регрессии в инструментах исследования кода (`codemap`); сбои разбора конфигураций при нестандартном форматировании `models.yml` и `config.yml`.
- **Рекомендация**: Добавить юнит-тесты для `codemap`, `glossary` и `replay`; перейти на стандартный парсер YAML или централизовать и зафиксировать тестами текущую реализацию.
