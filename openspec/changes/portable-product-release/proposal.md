# Why

The package can install configuration for eight hosts, but its current release checks do not certify one immutable npm archive on maintained Node releases across Windows/Linux/macOS. Core workflow commands still require users to know installed paths; automated review has an OMP/Bun dependency that must not be presented as universal native execution. Installation must recover safely from interruption and preserve user data. Existing comparative results do not prove development-quality benefit.

# What Changes

Deliver standard public npm installation and safe update, explicit capabilities/readiness and a usable CLI for core workflow operations. Certify exactly the archive that will be published, with release-source/integrity binding and actual hosted OS checks. Publish a reproducible, honest assessment of historical evidence and keep any positive quality claim disabled without adequate proof. Project-owned prompts may be aligned with verified behavior, not rewritten to justify unsupported claims. No new paid A/B experiments are authorized.

# Capabilities

- portable-runtime: recoverable data-preserving deployment, unified core CLI and honest native feature capabilities.
- release-certification: one-archive hosted certification, authenticated public npm release and provenance/integrity verification.
- honest-quality-evidence: validated historical outcomes, no-network replay/gates and source/version-bound claim limits.

# Impact

Existing installer/state/updater/doctor/CLI behavior and regression tests; npm package metadata and CI; benchmark/replay evidence consumers; existing managed workflow instruction surfaces and documentation. Personal/global machine settings and unrelated user files remain untouched. npm authorization is an external human prerequisite.
