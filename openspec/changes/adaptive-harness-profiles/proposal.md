# Adaptive harness profiles

## Why

Nullform currently installs largely the same coding workflow into different clients. In Hermes this adds a second task protocol, identity-level coding rules and six MCP registrations without checking native capabilities. Windows default-path resolution also disagrees with current upstream Hermes. Eight configuration adapters do not imply eight native execution integrations.

## What changes

Keep one npm package, but select a transparent host-specific profile. Reuse native mechanisms where evidence supports them; install lightweight verification guidance and portable tools for actual gaps. Unknown capability means unknown, not a reason to install another orchestrator or promise native support. Routine/general tasks do not acquire a coding state machine by default.

Hermes uses its resolved active profile, does not receive coding laws in SOUL.md, and does not get an unsolicited MCP bundle or the entire skill catalogue. Existing human settings remain protected. Other named clients receive the same adaptive-policy boundary while OMP retains its actual native strict integration.

A custom-host contract describes where project instructions belong and declares capabilities without supplying executable commands. This permits explicit integration with clients outside the named adapter list; it cannot guarantee that an undocumented client loads a file or has a working runtime.

## Validation and limits

Test deterministic behavior, ownership, containment, update routing and public CLI paths in isolated profiles. Compare the old and adaptive installations' actual registered modules, prompt bytes and execution time without equating overhead reduction with quality improvement. No new paid A/B; the general quality claim remains not-proven. The user's live Hermes profile is not changed. Actual native-runtime verification is reported separately from configuration/source verification.

## Scope

No package forks, LLM-based introspection service, parallel task database, credential inspection, automatic extra MCP installs, personal instruction edits or unsupported native-review fallback. Existing transaction and canonical-path protections remain mandatory.
