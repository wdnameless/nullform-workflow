# Interfaces and ownership

- **Gate + CI owner:** `tools/workflow.mjs`, `tools/tests/workflow-*.test.mjs`, `.github/workflows/repo-gate.yml`, `templates/ci/workflow-gate.yml`. Existing `cmdArtifact(root, flags)`, `cmdCheck(root)`, `cmdClose(root, flags)` remain public. Add `check-ci` CLI taking `--tier T0|T1|T2|T3` and `--change <id>` for T2/T3; validate committed change artifacts. PR must carry exactly one label `workflow:T0|T1|T2|T3`; CI requires it for pull requests and passes the tier/change from PR labels or changed OpenSpec path. Pushes still run deterministic tests. Do not use ignored `.workflow/state.json` as CI proof. Reject missing paths, REJECT, missing files, and any post-acceptance tracked/untracked/deleted source changes.
- **Dashboard owner:** `tools/dashboard.mjs`, `tools/tests/dashboard.test.mjs`. Keep `/api/state`, `/api/health`, `/api/diff` compatibility as needed. `/api/state` may expose only event kind, time, tool name, status and aggregate counters; it MUST NOT expose command arguments, message content, transcript names/paths, free-form event text or git diffs. `/api/diff` must not expose raw patch text; return only metadata (counts) or remove endpoint and UI interaction. Do not read/edit credential files.
- **Paseo + plugins owner:** `install.ps1`, `paseo/setup-paseo.ps1`, `paseo/profiles.json`, `agent/plugins.json`, `tools/doctor.mjs` plus their tests. Keep base install independent of Paseo. Clean `-SetupPaseo` without model warns/skips setup; explicit standalone call without model gives actionable error, preserving unrelated config. Required plugins: pi-lens and oh-my-pi-plugin-morph (tools used by mandated coding workflow); optional manifest entries warn. Exact versions, doctor/install share required classification. Never read or write model credentials.
- **Prompt owner:** `agent/AGENTS.md`, `agent/agents/orchestrator.md`, relevant prompt tests/baseline. Remove archmap mandate from source and deployed root; Wave 0 mandatory only T2/T3 for decisions the repo cannot answer. Source-to-live deployment needs checked parity; external user-home prompt is outside project root and is not directly edited.

Workers own disjoint files; no shared edits in their wave. Parent owns this OpenSpec change, integration, source-to-live sync and full verification. No new external package.
