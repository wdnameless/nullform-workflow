# Proposal — ci-green-selfheal

## Проблема

Три связанных дефекта делают харнесс хрупким:

1. **CI краснеет от истории.** `checkPushEvidence` проверяет каждый change,
   затронутый диапазоном push, против *текущего* дерева. `sourceDigest`
   включает весь worktree, поэтому любой коммит после приёмки навсегда
   инвалидирует архивные evidence. Диапазон 81c1f1b..HEAD содержит 18
   changes → push в master гарантированно красный.

2. **Установка требует человека.** `nullform init` при нескольких
   кандидатах падает с `ambiguous_harness`; чтобы выбрать, нужно читать
   меню. Агент не может поставить харнесс автономно и не спрашивает
   подтверждения плана перед записью.

3. **Нет восстановления.** Есть `doctor` (диагностика) и `update`
   (переустановка из registry), но нет команды «починить то, что
   сломалось, локально» — при повреждённом адаптере пользователь
   остаётся с красным doctor.

Плюс два сопутствующих: дашборд может молча не подняться, и один тест
зависает, из-за чего полный прогон не завершается.

## Что делаем

- **Историческая целостность evidence**: валидация push-гейта сверяет
  evidence с деревом *на момент коммита изменения*, а не с текущим HEAD.
- **`nullform setup`**: детект харнессов с объяснением причин, печать
  плана, подтверждение, установка. Non-interactive `--yes` для агентов.
- **`nullform heal`**: doctor → минимальное идемпотентное восстановление →
  повторная проверка. `--dry-run` обязателен и безопасен по умолчанию
  для разрушительных шагов.
- **Дашборд**: `workflow start` гарантирует живой URL либо явную
  деградацию с сообщением (никогда молча).
- **Зависший тест**: найти причину, устранить; полный прогон обязан
  завершаться.

## Не делаем

- Не меняем формат `review-evidence.json` (совместимость архивов).
- Не переписываем `doctor` — `heal` вызывает его как есть.
- Не вводим auto-merge зависимостей (уже решено в deps-policy).
