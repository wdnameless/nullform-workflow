# Требования — Apple-grade оболочка дашборда + функциональные пробелы

Запрос пользователя (verbatim):
«Проверь еще раз что можно взять из их репозитория, и давай сделаем наш дешборд более
стильным и функциональным по стилю apple»

Второй источник (verbatim): «Чем сейчас мы отличаемся от их дешборда, какие у нас слабые
места» — принятые из него пункты перечислены в R05–R08.

| ID | Verbatim user quote | Observable acceptance | Status |
| --- | --- | --- | --- |
| R01 | «более стильным … по стилю apple» | Оболочка построена на материалах, а не на плоских панелях: шапка и рельс — полупрозрачные слои с `backdrop-filter` (blur + saturate) и светлой верхней гранью; контент прокручивается под ними. Проверка: в сгенерированном HTML присутствует `backdrop-filter`, у шапки нет непрозрачного фона, `position: sticky` сохранён. | in-spec |
| R02 | «по стилю apple» — типографика | Размерно-зависимый трекинг: крупные заголовки с отрицательным `letter-spacing`, мелкий текст около нуля, ведущий интервал убывает с ростом кегля. Системный шрифт первым. Проверка: в CSS есть `clamp()`-заголовок с отрицательным трекингом и отдельное правило трекинга для мелкого текста; ни один `letter-spacing` не задан «на всё». | in-spec |
| R03 | «по стилю apple» — движение | Всё, что появляется/меняется, движется пружиной из текущего значения и прерывается: переходы на `transform`/`opacity`, `cubic-bezier`, а не `linear`/`ease` по умолчанию; ни одна анимация не блокирует ввод. Проверка: в CSS нет `animation` на макете, влияющем на раскладку; интерактивные состояния (кнопки, карточки, строки) имеют переходы на `transform`/`opacity`/`background`. | in-spec |
| R04 | «по стилю apple» — доступность | Три независимых сигнала: `prefers-reduced-motion` (кросс-фейд вместо движения), `prefers-reduced-transparency` (непрозрачный фон, без blur), `prefers-contrast: more` (чёткие границы). Проверка: все три медиазапроса присутствуют в CSS. | in-spec |
| R05 | «какие у нас слабые места» — ожидание пользователя | `workflow ask` пишет `state.waiting`, `workflow answered` закрывает и переносит в `waits`; дашборд показывает оранжевое состояние «ждёт тебя» и **останавливает** счётчик рабочего времени, вычитая ожидание из `activeMs`. Проверка: CLI-пара round-trip на temp-проекте; `waitMs` растёт, `activeMs` нет. | in-spec |
| R06 | «слабые места» — что нужно от тебя | Новый блок «Понадобится от тебя»: ключи из `.env.example` без значения, заглушки (`PLACEHOLDER`/`TODO:`/`defer:` с `ceiling`), допущения из `manifest.md`. Проверка: коллектор из фикстуры находит все три вида; блок рендерится с пустым состоянием, когда ничего нет. | in-spec |
| R07 | «слабые места» — приёмка | Карточка слепой приёмки: `matched / checked` и список расхождений R## из `oracle.md`. Проверка: из фикстуры `oracle.md` с «proven/partial/missing» считаются три числа и расхождения; при отсутствии файла карточки нет. | in-spec |
| R08 | «слабые места» — устаревшие проверки | Возраст кэша `dashboard-checks.json` показывается явно; старше суток — янтарный статус «устарело N дней», а не зелёное «всё ок». Проверка: коллектор на фикстуре с `generatedAt` 32 дня назад отдаёт `stale: true`, свежий — `false`. | in-spec |

Не-цели: замена бренда и цветовой системы (лаймовый акцент остаётся), перенос дашборда на
их `state.js`-модель, отказ от наших вкладок (архитектура/диффы/долг/история), внешние
библиотеки анимации.

Допущения (проверяемые): браузер целевого пользователя поддерживает `backdrop-filter`
(Chrome/Edge/Safari; при отсутствии — фон остаётся читаемым благодаря подложке);
`prefers-reduced-transparency` поддержан частично, поэтому правило — дополнение, а не
основа; ожидание пишется CLI, а не агентом-угадыванием.
