## Обоснование по осям (факты)

1. **SDD-порядок (9/9).** A: 8 стадий, код на 6-й, rule 5, G1–G4
   (SKILL.md). N: T0–T3 + openspec + oracle-gate, orchestrator не кодит
   на T2+ (AGENTS.md, workflow.mjs), G1–G4 в run-view. Ничья: жёсткость
   против гибкости тиров.
2. **Manifest (9/9).** A: verbatim R##, redaction, статусы, recount
   (1-manifest.md, ap.py). N: то же + типы R/Ri/G/A/D (requirements.mjs,
   brief.mjs, R02/R05 verified). Ничья.
3. **Briefing (9/6).** A: раунды с рекомендациями + adversarial pass
   как фаза + dials mode/depth (2-briefing.md, 2-adversarial.md,
   0-modes.md). N: dials есть (R01), чеклисты есть (R08), но нет
   фазового briefing-файла и интерактивных раундов — только Wave 0
   интервью. −3.
4. **Нарезка (9/7).** A: ~3K строк/тикет, волны, дизъюнктные зоны,
   wide change, check-plan (4-plan.md). N: G3-валидатор есть (R03),
   но нет калибровки по объёму кода и wide-change-правила. −2.
5. **Исполнение (7/9).** A: 1 тикет=1 агент, ≤3 в полёте, но shared
   working tree, исполнитель пишет тесты себе сам (5-subagents.md).
   N: изолированные worktrees, frozen tests, return contract + REDPROOF
   (R04). +2 нам: изоляция сильнее.
6. **Ревью (8/8).** A: точечное фоном + ветки F1 + лимиты ≤2/1
   (6-review.md, 5-repair.md). N: те же лимиты + 3 оси + F1
   (arbitrate.mjs, R09 verified). Ничья.
7. **Приёмка (8/9).** A: чистый git clone, спека запрещена промптом
   (8-final.md). N: то же + физический purge openspec/tickets/spec/
   manifest (blind-accept.mjs, R07). +1 нам: purge > запрет.
8. **Дашборд (9/9).** A: hero-цвет, трек, бары волн, слова, G1–G4, feed,
   waits-часы, snapshot (dashboard-template.html). N: всё это в run-view
   (R13 verified) + arch/diffs/debt/history, которых нет у A. Ничья
   с запасом: слоёв больше, баров волн пока нет.
9. **Память (9/8).** A: PROGRESS.md + carried.md + трейлеры + AGENTS.md
   для plain-сессий (9-memory.md). N: то же + skills-lock verify
   (carry.mjs, R11), но слабее инструкция plain-сессиям. −1.
10. **Метрики (8/6).** A: measure-run.py (роли, нормировка, трипвайры)
    + benchmark.md с цифрами двух прогонов. N: normalizedCost +
    cacheChurn-трипвайр есть (cost-snapshot.mjs), но нет своего
    benchmark-прогона с цифрами. −2.
11. **Установка (9/5).** A: `npx skills add`, 70+ агентов, skills.sh
    (README.md). N: install.ps1/sh + verify, нет skills-пакета. −4.
    Самый дешёвый балл для добора.
12. **Инженерия (6/9).** A: монолит ap.py 1075 строк, test_ap.py 33
    теста, regex-парсинг `|`, window.STATE. N: zero-dep модули
    (~11 файлов на R01–R13), 85 тестов зелёных, JSON-состояние. +3 нам.

## Что добрать для обгона (по цене балла)

1. **skills.sh-упаковка** (ось 11): SKILL.md + публикация. ~1 день. +2–3 к итогу.
2. **benchmark-прогон** (ось 10): один контрольный прогон + benchmark.md
   с цифрами. ~1 прогон. +1–2.
3. **briefing-файл + раунды** (ось 3): agent/phases/2-briefing.md +
   adversarial-интеграция в Wave 0. ~1 слайс. +1–2.
4. **Калибровка ~3K + wide change** (ось 4): правила в AGENTS.md +
   check-plan. ~полслайса. +1.
5. **Волны/бары в run-view** (ось 8): из plan-check данных. ~полслайса. Запас.

Итого: +6–9 баллов → **87–90 против их 84**. Обгон реален за 2–3 слайса.

## Честные оговорки

- Баллы 3, 4, 10 у нас ниже не из-за отсутствия механизмов, а из-за
  отсутствия упаковки/доказательств (фаза, цифры, пакет).
- Ось 5 и 12 — структурные преимущества (изоляция, модульность),
  которые им добрать дороже, чем нам добрать 3/4/10/11.
- Видео-кейс (11 часов, 65 требований, 4000 тестов) — их заявка без
  независимой проверки; наш benchmark нужен именно поэтому.
