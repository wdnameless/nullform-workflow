# Requirements — harness audit and simplification

User request (verbatim, in full):

> «Проанализируй наш воркфлоу найди ошибки и проблемы и слабые места.
>
> Я хочу улучшить его поддерживаемость, хочу чтобы у нас был минимализм в плане написания кода, чистый код, чистая архитектура. Которую поймет человек и ИИ агент. Что можно сделать ?»

This manifest atomises that request. Two halves: **find errors and weak spots** (R01–R08,
audit, delivered in this reply) and **improve maintainability / minimalism / clean
architecture understandable by a human and an AI agent** (R09–R16, the remediation plan).
Every finding below carries the evidence command actually executed on this tree.

Method note: four independent read-only scouts audited core tools, prompt surfaces,
install/sync, duplication and docs-claims. Subagent claims were treated as claims, not
evidence: each high-severity item was re-verified by a command in this session. One
subagent claim (`Atomics.wait` throws on the main thread) was **refuted** and is recorded
as such rather than carried into the plan.
