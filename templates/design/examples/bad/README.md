# Bad Design Examples (`docs/examples/bad/`)

This directory contains short, annotated negative references for the project.

## Convention & Guidelines
- **Purpose**: Clarify anti-patterns and rejected patterns explicitly before implementation. Examples demonstrate what to avoid (AI slop tropes, cluttered hierarchies, poor contrast, generic card repetition).
- **Format**: Short annotated notes, markdown files, image files, or URL references. Each entry should clearly state:
  1. What this sample is (e.g. `bad-feature-cards.png` or `purple-mesh-gradient.md`).
  2. Exactly what to avoid / reject from it.
- **Quantity limit**: Keep it bounded: **5 to 15 items maximum**. Curate strictly; focus on the most tempting or common anti-patterns for this project.
- **Storage**: No heavy binaries required. URLs, markdown annotations, or compressed screenshots are preferred.
- **Precedence**: When an example contradicts the approved Reference Lock in `docs/DESIGN.md`, the **Reference Lock always wins**. Any conflict must be explicitly reported.
