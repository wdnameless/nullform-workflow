# tools/workflow/

## Responsibility
Durable coordination state for cooperating agents and their isolated execution environments: task leases (claims) and workspace/worktree lifecycle. Deliberately **not** an OS-level filesystem sandbox — `claims.mjs` states this explicitly. The guarantee is cooperative exclusion over shared state, discoverable by any process reading the same workspace root. Workspace identities, roots, and containment checks fold Windows 8.3 short-path aliases and symbolic links through canonical native paths, ensuring two lexical spellings of a directory resolve to the same workspace.

## Design Patterns
- **Lease / Claim Registry (Durable Lock File)**: `claimTask`, `releaseTask`, `readClaim`, and `isClaimed` implement short, explicit leases: a claim is written to disk before work starts, read by peers to detect duplication, and released on completion. Acquiring an already-claimed active task fails with HTTP 409 (`already-claimed`), and overlapping canonical file scopes fail with `ECLAIMED` (both surfaced as exit code 3 in `runClaimCommand`). Staleness is resolved by ownership metadata and fenced generation tokens in the claim record, not by trusting a process.
- **Context Packet (Handoff Payload)**: `contextPacket` packages the bounded context a claiming agent needs (`contract`, `requirementsSource`, `goalAncestry`, `scope`, `verification`), validating pinned contract and requirement digests against `manifest.md` so a peer resumes from the packet instead of re-deriving it from the transcript.
- **Command Adapter & Confirmed Lifecycle**: `runClaimCommand` (`claim`, `release`, `context`) and `runWorkspaceCommand` (`workspace`, `integrate`) expose coordination primitives as CLI verbs so shell-level agents and tests drive the same code path as in-process callers. Destructive settlement of accepted changes via `cmdSettle` / `workflow settle` requires explicit operator confirmation (`--yes`, validated by `confirmSettle`) before tearing down worktrees and branches.
- **Boundary Discovery & Native Canonicalization**: both modules resolve the workspace root through `worktree-snapshot.mjs` (`validateRootPath`, `validatePathWithinScope`, `resolveRealPath`, `getCanonicalPath`, `isInsideOrEqual`) and `realpathSync.native` (`nativePath`). Windows 8.3 short names (e.g. `RUNNER~1` vs long paths) and Git repository pointers (`--show-toplevel`, `--git-common-dir`) are folded to their canonical native filesystem representation before state mutations, preventing lexical path divergence from creating orphan workspaces or misdirected lock files.

## Data & Control Flow
1. A caller resolves and canonicalizes the workspace root (`workspace` in `claims.mjs` via `resolveRealPath`, `projectRoot` in `workspaces.mjs` via `nativePath` / `realpathSync.native`) and issues a claim verb → `runClaimCommand` → `claimTask`.
2. `claimTask` acquires `.workflow/claims.lock`, reads existing claims, rejects double-claims on active tasks with code 409 (`already-claimed`), and rejects overlapping canonical file scopes (`samePath`) with `ECLAIMED`. Otherwise, it bumps the generation, issues a fresh UUID `token`, writes `.workflow/claims/<task>.json`, and returns the lease; `readClaim` and `isClaimed` provide read-only inspection without mutating state.
3. Work proceeds in an isolated worktree allocated by `workspaces.mjs` (`runWorkspaceCommand` `workspace` → `allocateWorkspace`), recording registration metadata (`.workflow/workspace.json` and git-common anchor `nullform-workspace.json`). When ready, `integrateWorkspace` (`runWorkspaceCommand` `integrate`) merges commits under `nullform-integration.lock`.
4. On completion or abort, `releaseTask` verifies the holder's `token` and sets `endsAt`; a crashed owner leaves a stale record that the next reader identifies by its recorded owner/timestamp.
5. `contextPacket` produces the durable handoff payload written alongside the claim, checking that pinned contract digests and manifest rows remain intact.
6. Post-acceptance retirement runs through `cmdSettle` (`workflow settle --change <name> --yes`), which enforces `confirmSettle` (`--yes`), refusing worktree and branch removal without explicit confirmation.

## Integration Points
- **Imports**: `../worktree-snapshot.mjs` — single source of workspace-root validation (`validateRootPath`, `validatePathWithinScope`), canonical path resolution (`resolveRealPath`, `getCanonicalPath`), and containment checks (`isInsideOrEqual`).
- **Consumers**: `tools/workflow.mjs` (tier/task lifecycle: `start`, `artifact`, `check`, `close`, `settle`), `tools/workflow-ci.mjs` (`cmdSettle`, `confirmSettle`, `checkQualityGates`), `tools/session-retro.mjs`, and tests (`tools/tests/workflow-*`, `tools/tests/task-claim.test.mjs`).
- **On-disk contract**: coordination records live under the workspace's `.workflow/` state directory (`.workflow/claims/<task>.json`, `.workflow/workspace.json`), locked by `.workflow/claims.lock` and `<commonDir>/nullform-integration.lock`; `tools/lead-time.mjs` consumes `.workflow/events.jsonl` for tier lead-time and pause medians.
- **CLI surface**: `runClaimCommand` (`claim`, `release`, `context`), `runWorkspaceCommand` (`workspace`, `integrate`), and `cmdSettle` (`workflow settle --change <name> --yes`). In-process callers use `claimTask`, `releaseTask`, `readClaim`, `isClaimed`, and `contextPacket` directly.
- **Known limit**: exclusion is cooperative — a process that never reads the registry is not stopped. Real isolation belongs to the worktree layer, not to this folder.
