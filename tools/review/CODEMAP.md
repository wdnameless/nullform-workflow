# tools/review/

## Responsibility
Controlled review execution and its audit chain: authorize what an oracle/reviewer may touch, spend against one durable money ledger, execute verified provider routes, and emit cryptographic evidence a later reader can re-validate. Splits into five roles — gatekeeper (authorization), budget (financial authority), executors (native in-process vs controlled HTTP), evidence projection, and arbitration — with cross-model routing acting as the route-selection and consensus layer above the executor. No layer trusts a claim from the layer above it; every fact is re-derived from raw artifacts.

## Design Patterns
- **Single Financial Authority (Ledger + Reservation)**: `budget.mjs` is the only place money is counted. One ledger per *project* (beside the verified Git common dir, never per worktree), integer nano-USD, discovery fails closed. Pins known provider routes (`PINNED_PROVIDER` / `PINNED_MODEL` / `PINNED_ENDPOINT` / `PINNED_TARIFFS_USD_PER_MILLION`, `GATEWAY_PROVIDER` / `GATEWAY_MODEL` / `GATEWAY_ENDPOINT` / `GATEWAY_TARIFFS_USD_PER_MILLION`) and validates user-configured routes via `validatePolicy` (forbidding OpenRouter). `admitSession` projects worst-case serialization growth against the 1 MiB bound (`MAX_LEDGER_BYTES`) and halts if any reservation is `held`. Charges are consumed durably *before* the physical wire call.
- **Settle-Compaction (Rollup Invariant)**: `ledger-compact.mjs` folds settled rows into a rollup to keep the ledger under 1 MiB while preserving `ledger.settledNanoUsd == Σ settled charges in reservations` — `partitionReservations` → `foldSettledMetadata` → `buildRollupReservation` → `compactLedger`. Idempotent by construction: folding changes shape, never the sum. `writeLedger` in `budget.mjs` automatically invokes `compactLedger` when ledger bytes exceed `MAX_LEDGER_BYTES`.
- **Gatekeeper / Pre-Call Authorization**: `gatekeeper.mjs` classifies tools into EXEC / WRITE / NETWORK danger categories (`DANGEROUS_EXEC_TOOLS`, `DANGEROUS_WRITE_TOOLS`, `DANGEROUS_NETWORK_TOOLS`), and `authorize` / `assertFactForcing` deny un-approved calls, keeping an audit log (`getAuditLog`, `clearAuditLog`).
- **Two Executors behind One Contract**: `native-tools.mjs` runs in-process product inspection (`inspectProduct`, `executeProduct`, `readProductPage` + `assertProductExecutionInvariant`); `http-runtime.mjs` is a bounded stdlib-Node Chat Completions executor (`runHttpReview`, `sendOnce`, `createHttpExecutor`, `isBrandedExecutor`) that locks to the policy's single admitted endpoint without retries, redirects, or fallback tiers. Reached through the tiny stdio child `http-child.mjs` (one JSON invocation on stdin, one result envelope on stdout, argv ignored) under verified Node (`resolveNodeRuntime`) with sanitized env (`sanitizedChildEnv`) and provider credentials (`credentialEnvForProvider`).
- **Cross-Model Routing & Dual-Oracle Consensus**: `cross-model.mjs` sits above the executor as the route-selection and verification layer. It coordinates execution preflight and consensus: `initReviewExecution` validates policy (`validatePolicy`) and initializes `createHttpExecutor` with `resolveNodeRuntime`; `checkProviderAdmitted` gates models against policy/credentials (`NULLFORM_GATEWAY_API_KEY`, `OPENAI_API_KEY`) and fails closed with `UNVERIFIED` (never simulated) when credentials are absent; `resolveReviewMode` restricts adversarial mode to reviewers; `parseCrossModelFlag` enforces `<provider>/<model>` syntax exclusively for oracle roles; `cleanReviewRunFlags` scrubs routing flags before child calls; `parseProductCommand` parses inspection commands; and `runCrossModelReview` coordinates dual passes via `runReviewRecord` (importing `loadReviewEvidence`, `saveReviewEvidence`), recording matching consensus (`recordMatchedVerdict`) or escalating divergences (`recordEscalatedVerdict`) without granting `ACCEPT`. Single passes and dry runs route through `handleSinglePassResult` and `handleDryRunResult`.
- **Performance Hot-Path Classification**: `hot-path.mjs` decides which changed files force performance benchmarks. Enforces the rule that a review must not demand a benchmark for a comment fix, nor wave through a hot path (latency changes to the live dashboard). `isHotPath` matches served runtime surfaces (dashboard servers, HTTP handling, collectors) while excluding inert file extensions (`.md`, `.txt`, `.json`, `.yml`) and test/fixture paths (`tests/`, `__tests__/`, `fixtures/`, `*.test.*`, `*.spec.*`). `classifyDiffForPerf` splits changes into hot paths (`requiresPerf`) and docs-only sets (`docsOnly`).
- **Re-Projection / Provenance Hash Chain**: `http-evidence.mjs` (`reprojectHttpExecution`, `projectHttpRecord`, `validateHttpRecord`, `extractVerdict`) rebuilds the record from the child's retained execution log plus raw provider response files, and captures immutable provenance in the child before the first wire call. `evidence.mjs` owns the hashes (`computeFileHash`, `computeSourceDigest`, `computeTestFilesHash`, `computeEventProjectionHash`, `computeManifestHash`, `computeRolePromptHash`) and the verdict regexes.
- **Historical Re-validation (as-of-revision)**: `evidence-history.mjs` — `validateReviewEvidenceAtRevision` — compares recorded hashes against the tree *at a revision*, because validating an archived change against HEAD fails on any later unrelated commit.
- **Arbitration / Scoring**: `arbitrate.mjs` (`arbitrate`, `scoreReview`, `consolidateF1`, `repairBudget`) turns findings into a verdict against acceptance criteria.

## Data & Control Flow
1. Scope & gate check: `hot-path.mjs` (`classifyDiffForPerf`, `isHotPath`) determines whether changed files touch runtime surfaces (dashboard, HTTP, collectors) and force performance benchmarking, or bypass perf gates if docs-only.
2. Authorization & route setup: Caller (`tools/workflow-ci.mjs` via `cmdReviewRun`, or `tools/auto-review.mjs`) validates review flags (`assertReviewRunFlags`), review mode (`resolveReviewMode`), and cross-model targets (`parseCrossModelFlag`). `gatekeeper.mjs` (`authorize`) checks permitted tools; `cross-model.mjs` (`initReviewExecution`) validates admission policy (`validatePolicy`), verifies Node runtime (`resolveNodeRuntime`), and initializes `createHttpExecutor`.
3. Financial reservation: `budget.mjs` (`admitSession`) checks existing held reservations, verifies ceiling limits, and projects ledger growth against `MAX_LEDGER_BYTES` before reserving nano-USD; `writeLedger` invokes `compactLedger` automatically if serialized byte length exceeds the 1 MiB limit.
4. Execution & consensus:
   - Single-pass review executes via `runReviewRecord` (native path via `native-tools.mjs`, or HTTP path via `http-runtime.mjs` spawning `http-child.mjs` with `sanitizedChildEnv` and provider credentials from `credentialEnvForProvider`).
   - Cross-model oracle review (`runCrossModelReview`) verifies secondary provider admission (`checkProviderAdmitted`); unadmitted providers halt as `UNVERIFIED` without simulation. If admitted, a second pass executes; matching verdicts produce consensus (`recordMatchedVerdict`), while divergent verdicts escalate (`recordEscalatedVerdict`) and deny `ACCEPT`.
   - Dry runs and single-pass results are routed via `handleDryRunResult` and `handleSinglePassResult`.
5. Evidence & Provenance: `http-evidence.mjs` re-projects records from child execution logs and raw provider responses; `evidence.mjs` writes/loads `review-evidence.json` (`loadReviewEvidence`, `saveReviewEvidence`) and validates cryptographic digests; `evidence-history.mjs` re-validates evidence at target git revisions.
6. Arbitration: `arbitrate.mjs` produces the verdict; positive/negative verdict recognition uses `isPositiveOracleVerdict` / `isNegativeOracleVerdict` (marker `LEGACY_MARKER`, file `EVIDENCE_FILE`), and `repairBudget` reconciles uncommitted attempts.

## Integration Points
- **Imports**: `../worktree-snapshot.mjs` (git-common discovery / repo boundary), `../installation/state.mjs` (path safety, identity), `../workflow-core.mjs` (state persistence for cross-model escalations), internals `budget.mjs`, `ledger-compact.mjs`, `gatekeeper.mjs`, `http-runtime.mjs`, `http-evidence.mjs`, `native-tools.mjs`, `cross-model.mjs`, `hot-path.mjs`.
- **Consumers**: `tools/workflow-ci.mjs` (`cmdReviewRun` imports `initReviewExecution`, `checkProviderAdmitted`, `resolveReviewMode`, `parseCrossModelFlag`, `cleanReviewRunFlags`, `runCrossModelReview`, `parseProductCommand`, `handleDryRunResult`, `handleSinglePassResult`), `tools/auto-review.mjs`, `tools/oracle-model.mjs` (route selection), `tools/quality.mjs` / review gate wiring, and `tools/tests/` (`cross-model.test.mjs`, `perf-gate.test.mjs`, `review-evidence`, `review-integrity`, `review-budget`, `review-boundaries`, `review-arbitration`, `review-controlled-http`, `review-execution` fixture).
- **Environment contracts**: `PROVIDER_CREDENTIAL_ENV` (`OPENAI_API_KEY`), `GATEWAY_CREDENTIAL_ENV` (`NULLFORM_GATEWAY_API_KEY`) via `credentialEnvForProvider`; `EXECUTION_FILE` holds the child's execution log consumed by re-projection; `EVIDENCE_FILE` names the durable evidence record.
- **State / artifacts**: project-level budget ledger (`BUDGET_LEDGER_FILE` under `BUDGET_LEDGER_DIR`, ≤ 1 MiB), review evidence JSON per change (`review-evidence.json`), child execution log (`execution.jsonl`) + raw provider responses.
- **Boundary rule**: `http-child.mjs` accepts nothing from argv; `ledger-compact.mjs` has no imports — it is pure data-shape work, which is what keeps the invariant testable in isolation; `hot-path.mjs` is a pure regex-based classifier with zero file system dependencies.
